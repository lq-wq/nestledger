# 备份与恢复

## 数据放在哪

容器内的 `/data` 映射到宿主机的 `./data`，结构如下：

```
nestledger/data/
├─ db.json          # 权威数据：房源、房间、租客、合同、账单、流水、提醒设置、合同附件（base64）
├─ meta.json        # rev（写入版本号）与最后写入时间
└─ backups/
   ├─ db-20261109-131000-r12.json
   └─ ...
```

- `web/index.html` 是纯代码，不含任何数据
- 浏览器的 `localStorage` 在 NAS 模式下只是**离线缓存**，删掉不影响服务端数据
- 主题偏好（白天 / 夜间）存在浏览器里，**不进入业务数据，也不进 JSON 备份**

## 三层备份

### 1. 自动快照（每次写入）

服务端在覆盖 `db.json` 之前，会先把上一版复制进 `data/backups/`，按 `BACKUP_KEEP`（默认 30）轮转。误删一条合同、误点「清空全部数据」，都能在这里找回上一版。

### 2. 页面里手动操作

「数据备份」页面在 NAS 模式下多出一张卡片：

- **立即生成快照**：不改数据，只留一份当前副本
- **刷新快照列表**：查看最近 15 份
- **下载**：把任意快照下载到本地（下载下来的就是完整 JSON，可以直接用「导入备份」还原）
- **导出完整数据（JSON）**：最通用的跨系统备份，单文件模式 / NAS 模式都可用

### 3. 目录级备份（推荐每周一次）

```bash
cd /vol1/docker/nestledger
./scripts/backup.sh
# 生成 ./backups/nestledger-data-20261109-131000.tar.gz
```

脚本会把整个 `data/`（含全部快照）打包，并只保留最近 30 份（可用 `KEEP=60 ./scripts/backup.sh` 调整）。建议再配合：

- 飞牛 NAS 共享文件夹的定时快照 / 存储空间冗余
- 定期把这个 tar.gz 复制到外接硬盘或私有网盘（异地副本）

> `./backups/` 已在 `.gitignore` 中，不会被推到 GitHub。

## 恢复方式

### A. 只要找回某几条数据 → 用快照

1. 「数据备份」→ 快照列表 → 下载对应时间点的 JSON
2. 先导出一份当前数据留底
3. 「导入备份」选择下载的 JSON → 确认覆盖

### B. 整台 NAS 迁移 / 目录损坏 → 用 tar.gz

```bash
cd /vol1/docker/nestledger
docker compose down
./scripts/restore.sh ./backups/nestledger-data-20261109-131000.tar.gz
docker compose up -d
```

脚本会要求输入 `yes` 才会覆盖，避免误操作。

### C. 只换了 NAS，数据还在

停掉两边容器，把旧机器的 `data/` 整个复制到新机器的 `nestledger/data/`，再启动即可。无需导入导出，附件和快照都跟着走。

## 备份检查清单

- [ ] `data/db.json` 存在且大小随录入增长
- [ ] `data/backups/` 里有最近几次保存的快照
- [ ] 页面「数据备份」能列出快照、下载能打开且是合法 JSON
- [ ] 至少有一份备份放在 NAS 之外（外接盘 / 另一台设备）
- [ ] 做过一次「导入备份」演练，确认真的能还原

> 数据含租客姓名、电话、身份证号与合同扫描件，属于敏感个人信息。备份文件请勿放进公开仓库或公共网盘分享链接。
